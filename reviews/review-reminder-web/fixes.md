## Fixed findings

### CR-1 — Reminder row is not refreshed after another row saves or reloads after a 412

Files changed:
- `web/src/app/features/settings/general/general-settings.ts`
- `web/src/app/features/settings/general/general-settings.spec.ts`

Problem:
At the end of `save()`, `refresh()` only covered the generic rows. When another row's save failed with a 412, the settings service reloaded every setting, but the reminder row kept showing the old value.

Fix:
At the end of `save()`, the stored reminder is now also shown with `showReminder(current)` when no reminder save is pending (`reminderPending === 0`). New spec: a theme save is answered by a 412, and the reload carries `weeklyReviewReminder: 'FRIDAY@08:00'`. The reminder row then shows Friday and 08:00.

Validation:
- `npx ng test --watch=false --include src/app/features/settings/general/general-settings.spec.ts` — Pass (48 tests)

### CR-2 — No feedback when the reminder time is emptied or invalid

Files changed:
- `web/src/app/features/settings/general/general-settings.html`
- `web/src/app/features/settings/general/general-settings.spec.ts`
- `web/src/locale/messages.xlf` (regenerated by `npm run i18n:extract`)
- `web/src/locale/messages.de.xlf`

Problem:
When a weekday was selected and the time field was emptied or invalid, nothing was saved and nothing told the user why.

Fix:
Added a `mat-error` to the time field that shows while the control is invalid: i18n id `settings.reviewReminder.timeInvalid`, English "Enter a time.", German "Gib eine Uhrzeit ein.". Angular Material shows it once the field has been touched. The stored time is not restored on blur; the error message was enough to fix the finding. New spec: emptying the time and leaving the field shows "Enter a time." and sends no PATCH.

Validation:
- `npx ng test --watch=false --include src/app/features/settings/general/general-settings.spec.ts` — Pass (48 tests)
